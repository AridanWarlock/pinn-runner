# Учёт задач

Backlog.md — источник статусов, приоритетов, зависимостей и результатов опытов.
Архитектура и методика остаются в docs/model-accuracy-plan.md; итоговые метрики
хранятся в numerical-reports и связываются с задачей и commit SHA.

## Одна доска для всех веток

Данные находятся в отдельном Git worktree .project-board, ветка
codex/project-tracking. Корневой backlog — локальная символическая ссылка на
.project-board/backlog. Оба локальных пути исключены из feature branch Git.
Переключение ветки кода не переключает данные доски. CLI для задач запускайте
из .project-board; Python-код изменяйте в основном checkout, не в папке доски.

Запуск на этом Mac:

```sh
cd /Users/user/Documents/ChatGPT/pinn_runner/.project-board
backlog browser
```

Обычный адрес: http://127.0.0.1:6420. Если сервер уже работает, остановите его
Ctrl+C в его терминале и запустите заново после изменения конфигурации.

Задачи коммитятся и публикуются отдельными коммитами ветки project-tracking.
Не cherry-pick/merge задачи в ветки модели; публикация сохраняет резервную копию
доски на GitHub. Рабочие ветки и их commits указываются в карточках задач.
Git-публикация кодовой ветки сама по себе не сохраняет изменения доски.
В конфигурации выключены automatic remote operations, auto_commit и сбор задач
из других веток: отсутствуют дубли и неявные сетевые операции.

На новом checkout создайте .project-board через git worktree add с веткой
codex/project-tracking и запускайте CLI/доску из него. Корневая ссылка — удобство
этого Mac, не обязательный шаг для Windows. Не архивировать и не удалять этот
worktree как временный: это постоянный checkout данных задач.

## Процесс

Статусы: Deferred, To Do, In Progress, Waiting CUDA, Review, Done.
Не ставить In Progress задаче только потому, что она следующая. Done означает
выполненные критерии и проверенный результат. Эксперимент может быть Done с
отрицательным выводом: это не то же самое, что принятие стратегии в default.

Перед работой читаем задачу и зависимости, записываем актуальный план. При
ожидании GPU — Waiting CUDA. В experiment notes сохраняем SHA, resolved config,
seeds, бюджет, путь/ссылку к отчёту, метрики, цену, вывод и следующую гипотезу.
Большие checkpoints в Git не кладём. Отдельно отмечаем подтверждённую,
опровергнутую гипотезу или недостаточность данных.

Сначала milestone m-0: текущий Torch/Lightning 2.1. Новые версии — milestone
m-1, задачи TASK-17…20 в Deferred с зависимостями от первого этапа.
TASK-12/13 условные: необходимость balancing/causality устанавливается опытами,
а не существованием карточки. Первыми идут TASK-1 (диагностика) и TASK-3 (loss).

Карточки создаём/обновляем через backlog CLI, не редактируем Markdown вручную.
Подробные правила: backlog instructions overview и соответствующие lifecycle
руководства. Нужен единый актуальный статус, а не дубликаты todo в разных .md.
