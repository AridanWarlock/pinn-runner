# Исследование PINN

Работай из корня репозитория; соблюдай `AGENTS.md` и инструкции Backlog.
Прочитай краткую карточку через `python3 scripts/research.py task TASK-N --criteria`,
затем её требования. Без номера `research.py tasks` помогает найти кандидатов,
но не разрешает автоматически начинать любую задачу.

Для математики прочитай [рабочий контекст](../../../docs/agent-research-context.md).
Полный вывод открывай по ссылке только для затронутого преобразования.
[Учебник](../../../docs/math-tutor.md) предназначен пользователю; не загружай его
для обычного исследования. Не перечитывай весь каталог экспериментов.

Назначь один проверяемый вопрос и критерий окончания блока. Различи точное
преобразование вычислений, изменение пространства функций и смену оптимизации.
Укажи предпосылки, сохраняемые величины и возможный контрпример. Для новых формул
обоснуй производные по физическим координатам, знаки нормалей, совместимость
начальных/граничных данных и пересечений граней. Проверяй производные и градиенты
по весам реальными численными тестами; моки подходят для транспорта, не математики.

До обучения зафиксируй код, матрицу случаев/начальных состояний, равный бюджет пар,
абсолютные пороги и критерии сравнения. Эталонное решение служит независимой
оценке, не скрытому обучению. Для удалённых опытов используй
[API](../../../docs/research-workflow-api.md); реализацию скриптов читай при
изменении или диагностике, а не перед каждым вызовом.

Отделяй статус процесса, полноту данных, абсолютную точность и парное сохранение
качества. Ускорение при равном числе шагов не равно ускорению до точности;
внутренние вычисления L-BFGS не равны внешним вызовам. Сохраняй неудачные результаты.
Не меняй основной режим по одному опыту или только `comparison_passed`: учитывай
число случаев/начальных состояний и происхождение исходников. Полные формулы и
предпосылки сохраняй в тематическом Markdown, данные — компактными проверяемыми
срезами, итог карточки — коротким со ссылкой.
