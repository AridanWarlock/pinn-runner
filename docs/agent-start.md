# Начало следующей сессии

Работай в `/Users/user/Documents/ChatGPT/pinn_runner`. Сначала прочитай `AGENTS.md`
и выполни `backlog instructions overview` в `.project-board`, как требуют правила.
Проверь `git status --short` и ветку. Не трогай чужие staged-файлы.

Это единственная точка входа для разработки. Не читать автоматически
`math-tutor.md`, всю карточку TASK-21 или каталог docs/experiments.
Длинные документы сохранены и доступны при необходимости; они не план на сегодня.

Дальше:

```sh
python3 scripts/research.py tasks
```

Выбери задачу по поручению пользователя, затем вызови `task TASK-N --criteria`
и прочитай ссылку требований. Не выбирай работу только по порядку списка.
Описание списка: `docs/research-task-index.md`. TASK-27–31 завершены:
команды `submit`, удалённые статус/отмена/сбор реализованы. Результаты и
ограничения — `docs/research-queue-result-2026-10-17.md`, контракт —
`docs/research-workflow-api.md`. Для сбоя начни с `diagnose`, затем открывай
только нужный ограниченный хвост; требования — `docs/research-diagnostics.md`,
итог — `docs/research-diagnostics-result-2026-10-17.md`.
Перед новой отправкой выполни `plan --manifest protocol.json`: проверка без Torch
показывает бюджет и отклоняет несовместимые варианты до SSH. Требования и границы
проверки — `docs/research-planning.md`.
Сначала проверь, есть ли новое поручение;
не продолжай автоматически инфраструктуру или прежние эксперименты.

Если возвращаешься к математике модели, сначала `docs/agent-research-context.md`,
затем требования TASK-21 из `docs/research-tasks/task-21.md`. Новых обучений
не требуется для знакомства с проектом. На момент передачи все серии завершены.
Последняя — density010: `docs/density-neumann-result-2026-10-17.md`. Она подтвердила
строгую точность затухающей моды 2D на пяти seed при обеих плотностях 1024/4096
и бюджете 60 с; не переносить это на прежний бюджет 008, 3D или другие исполнители.

Просмотр задач и `plan` не запускают обучение. `submit` запускает его по
опубликованному протоколу; ограничения — `docs/research-workflow-api.md`. Зависимости не обновлять, основные настройки
не менять без отдельного решения по доказательствам.

При старте следующего рабочего блока назначь один вопрос и критерий окончания.
Сохраняй новые выводы в основном отчёте; в карточке — короткий итог со ссылкой.
Объяснения для пользователя и математические выводы не сокращать ради контекста:
оптимизируется загрузка документов, а не их содержание.

Проектные скиллы:
- `pinn-research` — математическая гипотеза, протокол и интерпретация результатов.
- `pinn-gpu-experiments` — существующая Windows-очередь и диагностика.

Они находятся в `.agents/skills/`; загружай только подходящий к поручению.
Для отдельного учебного чата используй `docs/math-tutor.md`, начиная с одной темы.
Новая сессия не должна загружать всю историю ради восстановления контекста.
