# TASK-39.4: целые коды функции и согласованная выборка

Контракт `parameter_rows` принят по проверкам представления, физических
производных и файлового цикла. Это **не приёмка точности сети на новых формах**.
Обучение качества разнообразных функций остаётся TASK-39.5.

[Контракт и математика](surrogate-parameter-rows.md),
[перспективный протокол](function-code-admission-protocol-2026-10-21.md),
[публичный API](API.md). Исходники `f71bc18377942dfe84e066c1b8620945c56d140b`,
протоколы `2a09822cbe191cf31ddc02705cdb594974c36f32`.

## Что изменилось

`domain.parameter_rows` задаёт список целых кодов в порядке имён параметров;
`prediction.parameter_rows` — новые целые запросы. Сетка пересекает физические
узлы со списком гипотез, а LHS выбирает код целиком. Исходная нормализация
сохранена, порядок запросов устойчив. Повторы, bool, нечисловые значения,
неверные размеры и смешение независимых запросов со строками отклоняются.
Прежний независимый режим без нового поля сохранён.

Для контроля взят положительный косинусный класс из двух коэффициентов
логарифма k. Внутри него кодирование точно в вещественной арифметике;
произвольная функция не обязана входить в этот класс. Для приближения
логарифма отдельно приведена оценка ошибки представления коэффициента.
Таблица не является декодером: математический смысл кода задаёт источник Problem.

## Наборы и наблюдения

- Полный CPU `scripts/check.py --full`: Ruff, format, strict mypy,
  **1066 тестов**, файловые сценарии не исключались. Затем отдельно пройдены
  усиленные четыре численные и два файловых сценария, включая новый вариант
  совместимости прежнего независимого режима с запросом целых строк.
- Данные: 19 профильных CPU-контролей, в том числе области 1D/2D/3D.
  При 24 признаках, 100 объявленных узлах каждого признака и трёх целых кодах
  основная сетка имеет форму 9 x 2 x 25, 450 чисел. Компоненты кода не попадают
  в meshgrid; произведение 100²⁴ не строится. Это проверка размера массива,
  не измерение памяти процесса и не качество 24-признаковой модели.
- При LHS все коды входят в исходный список, IC/BC/PDE сохраняют согласованные
  строки. Повтор с тем же seed воспроизводит выборку; внешняя мутация исходной
  таблицы не меняет список кодов сохранённого объекта сетки.
- CUDA `cs394n1021`: **4/4**, compare=true. Реальные FCN, 2305 параметров,
  состояния 11/29, FP32/FP64; все градиенты, четыре конечные разности FP64,
  перестановки и разбиения партий, начальные и граничные условия,
  неизменность состояния. Шагов оптимизатора нет.
- CUDA `cs394f1021`: **2/2**, compare=true. По три Adam и два внешних L-BFGS
  для каждого режима и по одному восстановлению с шагом 1e-300. Новые строки
  (.4,.16), (-.4,.16) совпали с прямым воспроизведением весов. Изменение
  декодера, перестановка входов и выход за интервалы отклонены; файл модели
  не изменился. Этот малый цикл не означает точности обученного суррогата.
- RTX 4070 Ti, Torch 2.1.0+cu118, CUDA 11.8, TF32 выключен. Тесты выполнялись
  в прежней штатной очереди с отдельными опубликованными SHA, collect/compare.

## Границы и следующий этап

Проверена передача целой гипотезы, а не универсальная архитектура операторной
сети. Хранение физической сетки остаётся линейным по числу гипотез и растёт
с размерностью физической области. Нахождение нового кода внутри интервалов
не гарантирует качество, особенно вне распределения обучающих гипотез.

Следующая задача — аналитическое семейство действительно разных форм k(x)
при одинаковых начальных/граничных данных и нулевом источнике. Код должен
различать формы, а независимый эталон — менять поле, а не подбирать источник
под одно заранее фиксированное решение. До нового обучения нужны собственный
эталон с контролем его погрешности и перспективная матрица новых гипотез.
