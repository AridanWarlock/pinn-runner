# Переменная теплопроводность: короткая численная CUDA-приёмка

## Один вопрос

Переносятся ли на целевую RTX4070Ti проверенные CPU-невязка консервативной
теплопроводности и градиенты всех весов при формуле/таблице одного коэффициента?
Обучение сходимости, скорость и смена defaults в этот опыт не входят.

Используется существующая очередь и `numerical-acceptance`, contract6.
Регистрируется третий фиксированный набор
`tests/numerics/test_variable_conductivity_network.py`: ровно16 nodeid,
никаких произвольных pytest-путей. Таймаут300с без продления.
Исходники и машинный протокол публикуются разными коммитами до запуска;
протокол фиксирует полный SHA кода и LF-нормализованный SHA тестового файла.
Защита сырых байтов и неизменяемого снимка сохраняется.

## Матрица и контроль

-8 сценариев настоящей сети: FP32/FP64 ×1D/2D ×beta0/1, seed19.
  Каждый сценарий проверяет **обе** формы коэффициента; всего16 моделей.
  Все2273/2337 скалярных параметра участвуют в сравнении градиентов.
-8 сценариев точного поля: FP32/FP64 ×1D/2D ×формула/таблица, beta1.
  Правильный оператор должен давать нулевую невязку, пропуск производной
  коэффициента — известную ненулевую ошибку.
- Сеть32×32×32, полиномиальные Neumann-признаки, точные IC/нулевой поток,
  `hard_execution=eager`, общий фон. Никаких шагов оптимизатора.
- Точки/независимый NumPy-источник/раскрытие дивергенции совпадают с
  [CPU-протоколом](variable-conductivity-network-protocol-2026-10-19.md).
  Для FP64 дополнительно8 направленных конечных разностей h=1e-4.
- Тесты явно требуют размещения поля и параметров на выбранном CUDA-устройстве;
  успешная CPU-ветвь не считается выполнением CUDA-приёмки.

Среда: Windows, RTX4070Ti, Torch2.1.0+cu118, CUDA11.8, исходный default FP32,
`highest`, TF32 отключён. Набор временно переводит выбранные модели в FP64,
но не меняет глобальный dtype. Windows-каталог всегда `C:\Projects\pinn-runner`.

## Заранее заданные критерии

Все16 сценариев и48 фаз setup/call/teardown должны завершиться успешно;
skipped/xfail/xpass и ошибка завершения не принимаются. Состояния моделей
до/после диагностических возмущений должны совпасть по SHA, исходники не меняются.
Численные пороги сохраняются с CPU:

- невязка и каждый градиент: FP32 rtol2e-4/atol5e-6;
  FP64 rtol1e-10/atol1e-11;
- направленная производная: abs≤5e-7+2e-5·abs(D);
- IC max≤2e-6 FP32/1e-11 FP64, поток max≤2e-5 FP32/1e-11 FP64;
- поля формулы/таблицы внутри пары должны совпасть точно;
- ненулевой функционал>1e-5, норма его градиента>1e-5;
- точный отрицательный контроль пропущенного члена должен быть ненулевым.

Критерий окончания: штатные collect в новый пакет и compare, полный перечень
исходов, сохранённые ошибки при неудаче. При ошибке сначала diagnose,
не новый запуск/таймаут. Результат не заменяет20 будущих обучений,
пяти начальных состояний на физический случай или CUDA-файловый цикл.
