## Цель и стиль работы

Это одноразовый файловый решатель, не сервер: внешний сервис запускает его
в изолированном Docker-контейнере; он читает `config.yaml` и `functions.py`,
обучает модель, сохраняет результаты и завершается. Точное решение из `data.mat`
не требуется ни обучению, ни предсказанию. Аналитический ответ в бенчмарках
используется только для независимой оценки. Обратную задачу восстановления
неизвестных физических коэффициентов сейчас не решаем.

Глобальные цели: 1D–3D, варьирующиеся входные параметры, пространственные поля
коэффициентов, читаемый и расширяемый код. Значительная часть уже реализована;
текущий фокус — точность и стоимость точных ограничений для теплопроводности
на декартовых прямоугольниках, без обновления зависимостей.

Пользователь пришёл из типизированных языков и изучает Python. Нужны явные типы,
Ruff, strict mypy, понятные имена и короткие методы; устаревший код можно удалять.
Объясняй ключевые решения по-русски, при запросе — подробно механику Python/Torch.
Изменения делай содержательными блоками, не отдельной веткой на каждый коммит.
Формулы пиши только отдельными блоками `$$ ... $$`: встроенная запись не видна.

## Что уже умеет код

Основной поток:

```text
run.py → TaskApplication → TaskSettings + Problem
       → SolverFactory / ProblemAdapter / ConstraintPlan
       → FCN + PINNModule + Lightning
       → SolverExecution → ArtifactWriter
```

Пользователь экспортирует `problem = Problem(...)` из `functions.py`.
`Problem` содержит поля, уравнения, обязательную начальную функцию и функции
граничных данных. `Coordinates` предоставляет физические координаты и параметры;
`Equation` — `field`, `diff`, `dt`, `gradient`, `laplacian`, `divergence`.
Производные считаются через autograd; сеть обучается по невязке PDE.
Точный синтаксис конфигурации бери из `docs/API.md`, не из старых диалогов.

Есть пространственные измерения 1D–3D и время, скалярные параметры семейства,
коэффициенты-функции и фиксированные табличные поля с дифференцируемой
многолинейной интерполяцией. Таблица коэффициента — фиксированное свойство задачи,
а не произвольный тензорный вход обученного оператора. Подробности: `docs/coefficients.md`.
Не все эти возможности совместимы с каждым режимом точных ограничений.

Режимы:

- `soft` — общий режим по умолчанию, штрафы за начальные/граничные условия.
- `hard_initial_dirichlet` — точные совместимые начальные и все грани Дирихле;
  ненулевые, зависящие от времени значения поддержаны. Есть отдельные способы
  вычисления `eager`, `fused_predict`, `product_rule`; смотри ограничения API.
- `hard_initial_robin` — точные начальные условия и все грани Неймана/Робина,
  одно поле, 1D–3D. Внутри этого явно включённого режима default — `robin_grouped`.
  Альтернативы: контрольный `eager` и экспериментальный `robin_batch`.

Общий default НЕ был переключён на hard. Для Robin пока исключены `beta=0`,
смесь с Дирихле, `heat_flux`, параметры семейства и пользовательские выходные
преобразования. Коэффициенты граничных операторов постоянны; данные гладкие,
поточечные и сохраняют граф. Нужны все грани без повторений.
Проверяется начальная и межгранная совместимость на сетке в float64;
эта проверка не доказывает тождества между узлами или корректности самой PDE.

Сохранённая модель учитывает источник функций и физические граничные операторы.
Для Robin интервалы пространства/времени должны совпадать, разрешение менять можно.
Адаптер исполнения можно менять: он не меняет математическое представление.

## Математическое ядро последнего этапа

На гранях по оси i оператор имеет вид:

$$
L_{i,s}u=\alpha_{i,s}u+\beta_{i,s}n_s\partial_{x_i}u,
\qquad n_-=-1,\quad n_+=1.
$$

Нормальная производная и физический тепловой поток различны: поток равен
минус теплопроводность, умноженная на нормальную производную.
При длине отрезка L и нормированной координате s строятся кубические функции:

$$
\phi_-=-\frac{L}{\beta_-}s(1-s)^2,\qquad
\phi_+=\frac{L}{\beta_+}s^2(s-1).
$$

Они нулевые по значениям на обоих концах и удовлетворяют кардинальному
условию граничных операторов. Обозначая продолжение следов через P, получаем:

$$
P_iF=\sum_s\phi_{i,s}L_{i,s}F,\qquad Q_i=I-P_i,
\qquad L_{i,s}Q_iF=0,\qquad Q=\prod_i Q_i.
$$

Для постоянных коэффициентов, отдельных осевых базисов и достаточно гладких
функций проекторы разных осей коммутируют. Межгранная совместимость данных:

$$
L_{j,r}h_{i,s}=L_{i,s}h_{j,r}.
$$

Это не равенство значений разных граней. Продолжение данных A строится
последовательно с вычитанием пересечений. При согласованном начальном поле g:

$$
u_\theta=g+A[h(t)-h(t_0)]+\tau QN_\theta,
\qquad \tau=\frac{t-t_0}{T-t_0}.
$$

Начальное и граничные условия точны по конструкции; обучается невязка PDE.
Доказательства, полнота представления для гладких допустимых функций и
предпосылки: `docs/robin-box.md`. Не дели невязку на обнуляющиеся множители.
Не отсоединяй граф обучения ради кэша. Разрешённый кэш содержит только постоянные
коэффициенты операторов по устройству/типу, а не значения сети между шагами.

Прямой способ вызывает сеть 3^d раз. Групповой — 2^d раз, объединяя стороны
фиксированного набора осей и считая нужные смешанные нормальные производные.
Число обрабатываемых строк остаётся 3^d на исходную точку: это не снижение
размерности задачи. При предсказании можно не строить граф последней нормальной
производной; при обучении зависимости по весам сохраняются полностью.

Ключевые файлы:

- `pinnstorch/training/robin_projection.py`, `robin_initial.py`, `robin_box.py` — математика.
- `pinnstorch/training/robin_batch.py`, `robin_grouped.py` — способы вычисления.
- `pinnstorch/runner/robin.py`, `robin_validation.py`, `constraint_plan.py` — сборка и проверки.
- `benchmarks/cases.py`, `benchmarks/box_heat_balance.py` — аналитические задачи и баланс.

3. Только отдельным опытом проверить усиление выборки около граней/пересечений
   и конца времени. Это дополнительная невязка PDE, а не повторный штраф
   за уже точные граничные условия. Применимость требует гладкого решения.
4. Параллельно по смыслу, но без смешения причин, измерить стоимость продолжения
   данных и производных сети. Любую алгебраическую оптимизацию сначала доказать,
   затем сравнить значения, первые/вторые/смешанные производные и градиенты весов.
5. Пороги и бюджет задавать до опытов. Отдельно показывать общий/последний/худший
   временной L2, невязку PDE, начальные/граничные операторы, баланс, модальные
   ошибки, время обучения/предсказания, память и число вычислений L-BFGS closure.

Начни с короткого опыта и двух парных состояний; расширяй матрицу только при
сигнале пользы. Новые зависимости и понижение точности не смешивай с прозрачной
оптимизацией текущего FP32. Не обещай улучшение всех PDE по одной тепловой задаче.
