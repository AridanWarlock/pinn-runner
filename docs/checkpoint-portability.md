# Перенос сохранённой модели между Windows и macOS

В этом блоке проверен настоящий checkpoint, обученный на Windows RTX 4070 Ti,
на Mac M1 с CPU. Он сначала не загрузился: `torch.load` пытался восстановить
`pathlib.WindowsPath` и получал `NotImplementedError`.

Причина оказалась в служебном поле `callbacks/ModelCheckpoint.../dirpath`:
каталог передавался Lightning как объект `Path`, и тот сохранялся вместе
с тензорами. На своей ОС такой путь работает, на другой нельзя создать
его файловый объект. Веса и CUDA-хранилища здесь не были причиной:
`map_location="cpu"` корректно переносит тензоры, но не преобразует пути.

## Исправление

- В новых сохранениях каталог ModelCheckpoint передаётся строкой. Строка
  сохраняет имя, не требует создания платформенного файлового объекта.
- `runner/checkpoint_io.py` задаёт единый путь чтения сохранённого состояния.
- Его небольшой кодек pickle заменяет только **чужие** классы `WindowsPath`
  и `PosixPath` на `PureWindowsPath` и `PurePosixPath`. Это символические пути:
  они умеют хранить/разбирать имя, но не выполняют файловых операций другой ОС.
  Родные классы текущей ОС остаются прежними.
- Глобальная подмена `pathlib` не выполняется. Изменение ограничено конкретным
  вызовом загрузки, поэтому не влияет на параллельные проверки или обычный IO.
- Чтение весов для `predict/retrain` и инструментов оценки использует этот
  загрузчик. Формат тензоров и оптимизаторов не меняется. Публичный `retrain`
  по-прежнему начинает новую оптимизацию из весов, не восстанавливает чужие
  каталоги callback или старую историю обучения автоматически.

Кодек использует штатный параметр `pickle_module` в `torch.load`; типизированные
границы отделяют разнородные метаданные от численного кода. Это тот же полный
формат состояния Lightning, а не новый формат модели.

## Проверка

Проверены ZIP-формат Torch и прежний формат сериализации, оба вида платформенных
путей, точное сохранение тензоров/состояния оптимизатора, отсутствие глобальной
подмены классов. Файловый сценарий подставляет чужой путь в настоящий checkpoint
и затем выполняет публичные `predict` и `retrain`.

Дополнительно скачан настоящий CUDA-checkpoint и соответствующий MAT. На Mac
посчитаны 729 значений последнего слоя и сравнены с сохранённым результатом GPU:
максимальное различие **9,54·10⁻⁷**, допуск 3·10⁻⁵. Один CPU-проход занял
0,0215 с. Это проверка переноса, не CUDA-приёмка и не устойчивый замер скорости CPU.
Нового обучения не проводилось. Исходный checkpoint на Windows не изменён.

[Исходные метрики переноса](experiments/2026-10-15-checkpoint-portability.json).

Тот же файл дополнительно прошёл **публичный CLI predict** на Mac для всех
22 599 значений: максимальная разница с GPU снова 9,54·10⁻⁷, полный запуск
с подготовкой, вычислением и записью результатов — 3,00 с. Это отдельный
проверенный путь, а не вывод только из загрузки `state_dict` в памяти.
Профильные тесты — 6 пройдено; отдельный файловый сценарий predict/retrain —
1 пройден за 6,26 с; полный CPU-набор после изменения чтения — 498 пройдено за 255,75 с.

Финальный повторный полный набор после изменения политики обратного прохода:
**499 passed, 261,36 с**, Ruff lint/format и strict mypy — без ошибок.
