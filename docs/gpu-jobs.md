# Фоновые CUDA-задания

Mac управляет заданиями через `python -m scripts.gpu_jobs`; Windows выполняет
их через отдельный фоновый SSH-процесс на Mac. Нужны настроенный alias `aridanPC`, Python .venv
и опубликованный commit с поддержкой GPU jobs. Перед первым запуском обновите
Windows-копию на нужную ветку через обычный SSH workflow из AGENTS.md.

```sh
python -m scripts.gpu_jobs start --case heat3d --steps 6000 --seeds 1234 4321 --timeout-seconds 3600
python -m scripts.gpu_jobs status --job-id JOB_ID
python -m scripts.gpu_jobs collect --job-id JOB_ID
```

По умолчанию start закрепляет HEAD Mac-копии; можно задать полный SHA через
`--commit`. Commit должен существовать в Windows Git object database после fetch.
У каждого задания отдельный каталог `C:\Projects\pinn-runner\.gpu-jobs\JOB_ID`:
request.json, status.json, run.log, checkout, results. `collect` копирует статус,
запрос, общий лог и report.json на Mac в numerical-reports/collected/JOB_ID.
Большие checkpoints/MAT остаются на Windows; collect не удаляет исходные файлы.

Код берётся из `git archive` закреплённого SHA. Это снимок, а не переключаемая
рабочая ветка: последующие pull/изменения основной Windows-копии его не меняют.
Все процессы и Git-команды запускаются **из корня C:\Projects\pinn-runner**;
импортируемый код, входы, результаты и кеши находятся в подкаталогах. Переменная
PINN_WORKING_DIRECTORY сохраняет этот cwd даже для вложенных runner-процессов.
Снимок маркирует отчёт точным SHA через PINN_PINNED_REVISION. Python bytecode
запись отключена для worker; GPU/Matplotlib/temp кеши находятся внутри задания.

`start` запускает отдельный SSH-процесс на Mac и сразу возвращает управление.
SSH остаётся открытым до завершения worker; лог соединения лежит в
numerical-reports/gpu-connections/JOB_ID.log. Завершение текущей команды или
работы над веткой не останавливает этот процесс. Mac и Windows должны оставаться
включёнными и соединёнными: закрытие SSH, потеря сети или перезапуск Mac могут
оборвать вычисление. Полностью независимый от SSH запуск пока не поддерживается:
WMI на этом Windows отказал в доступе, а Start-Process не пережил отключение SSH.
Системные права и настройки мы не меняем.
Windows-файловая блокировка допускает только одно активное CUDA-задание;
остальные процессы ждут в состоянии queued. Порядок захвата не гарантирует FIFO.
Лимит времени начинается после захвата GPU, а не во время ожидания очереди.

Статусы: queued → running → passed / failed / timed_out. running обновляет
updated_at примерно раз в три секунды; после завершения сохраняются exit_code
и finished_at. Timeout останавливает дерево benchmark-процесса через taskkill,
а логи и частичные результаты сохраняются. ПК должен оставаться включённым;
сон/перезапуск Windows не поддерживают продолжение optimizer state.

Во время задания можно продолжать работу в другой ветке на Mac. Не обновляйте
общую Windows .venv во время активного задания: закреплён код, но среда Python
общая. Новый commit проверяется новым заданием, а не старым результатом.
Никогда автоматически не считать queued/running успешной приёмкой. Если heartbeat
устарел, проверьте PID worker и лог; после внезапного уничтожения worker статус
может остаться последним сохранённым. В этой версии нет авто-восстановления
после перезапуска Windows и нет команды отмены.

Для ожидания результата после завершения чата можно создать временную
автоматизацию проверки status через SSH. Само выполнение GPU-задания от этого
мониторинга не зависит. Автоматизацию отключаем после сбора результата.

3D-бенчмарк: u=sin(πx)sin(πy)sin(πz)exp(−0.3π²t), уравнение u_t−0.1Δu=0,
нулевые границы куба, x/y/z в [0,1], t в [0,0.5]. Оценочная сетка 17³×31
(152 303 точки), IC/BC-сетка 8³×11, PDE — 1024 LHS-точки. Для старых трёх
задач настройки и baseline сохранены; heat3d выбирается явно через --cases.

## Первый 3D-прогон на RTX 4070 Ti

Задание heat3d-005, commit 389d599, FP32, 6000 шагов на каждый seed:

| Seed | Relative L2 | L2 на последнем времени | Обучение | Тёплый инференс всей сетки |
| --- | --- | --- | --- | --- |
| 1234 | 4,68% | 12,80% | 53,77 с | 20,98 мс |
| 4321 | 5,76% | 15,81% | 53,76 с | 20,27 мс |

Обучение — около 111,6 шага/с; тёплый инференс — 7,26–7,51 млн точек/с.
Полный predict с запуском runner и записью результата занимает 2,32–2,36 с.
Статус **failed**: seed 4321 превышает общий порог relative L2 ≤ 5%.
Последний временной срез пока только диагностическая метрика: его заметно большая
ошибка показывает, почему общего L2 недостаточно для оценки всего решения.
Этот прогон не принят как эталон качества, пороги ради него не менялись.
