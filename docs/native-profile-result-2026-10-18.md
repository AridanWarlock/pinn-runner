# TASK-21: причина отсутствия CUDA-событий и нативная трасса

## Наблюдаемая причина

На Windows из обязательного `C:\Projects\pinn-runner` проверены установленная
среда и исполняемые файлы. Нагрузка GPU при этой диагностике не запускалась.
Torch 2.1.0+cu118 сообщает `kineto_available=True`, но поддерживает только
`ProfilerActivity.CPU`. В фактических флагах сборки одновременно присутствуют
`USE_KINETO` и `LIBKINETO_NOCUPTI`. Это объясняет, почему прежняя проверка
Kineto не обеспечивала CUDA-событий даже при наличии DLL CUPTI.

Nsight Compute 2023.1.0 доступен через PATH. Nsight Systems 2023.1.2.43 найден
в установленной папке `target-windows-x64`; отсутствие команды в PATH нельзя
было трактовать как отсутствие инструмента. Проверка Nsight Systems вернула
`Administrator privileges: No`, `Sampling Environment: Fail`.
Справка уточняет, что административные права нужны для включённого CPU sampling;
режим `--sample=none` его отключает. Эти ответы не доказывают ни успех,
ни невозможность захвата CUDA: для этого нужна настоящая нагрузка.

Проверен последний процесс analytic012: `completed`, exit 0; файл блокировки
существует, но это постоянный файл для байтовой блокировки, а не признак занятого
GPU. Файл не удалялся. Проверена исходная конфигурация и SHA256 единственного
сохранённого состояния для следующего опыта.

## Новый ограниченный инструмент

Для соблюдения единой очереди добавлен контракт 3 `frozen-profile`:
фиксированный сценарий, два процесса, прежняя общая блокировка/таймаут/
Windows Job Object и неизменяемый снимок кода. Произвольные команды протоколом
не принимаются. Источник весов и конфигурации проверяется по SHA256.

Нагрузка использует существующий сценарий парного контроля поля/невязки/
градиентов; добавлены NVTX-метки физического поля, невязки и градиента по весам.
При внешней трассе внутренний Torch profiler выключен, время явно помечено
как полученное с профилировщиком. Сбор проверяет контрольные суммы сырых файлов
на Windows и передаёт компактную сводку. SQLite читается только для чтения;
суммарная длительность событий не называется временем процесса.

Протокол и математика: [native-profile-protocol-2026-10-18.md](native-profile-protocol-2026-10-18.md).
Контракт подробно описан в `research-workflow-api.md`. Один успешный захват
не закрывает полный профиль TASK-21 и не даёт права менять defaults.

## Итог native013: отрицательный результат

Очередь завершила обработку и сбор двух записей. Обе команды Nsight вернули
код 0, но обе отказали **до запуска нагрузки**:

> Microsoft-Windows-DxgKrnl provider requires administrator privileges

Исключение: `QuadDCommon::AccessDeniedException`, запуск ETW session.
Отчётов нагрузки нет, событий CUDA и нативных отчётов нет.
`compare` корректно вернул `comparison_passed=false`,
`cuda_trace_captured=false`. Ни код возврата 0, ни статус очереди `completed`
не были ошибочно приняты за успех профилирования.

SHA256 весов и конфигурации после каждой попытки прежние. Обучение и обновления
весов не выполнялись. Ошибка одинаковая у обоих правил; выводов о быстродействии
или качестве модели она не даёт. Изменения доступа и автоматический повтор
не выполнялись. Нагрузка этой серии и наблюдатель завершены.

[Компактное доказательство](experiments/2026-10-18-native013-summary.json)
содержит протокол, фактическую среду, SHA, хвосты ошибок и отпечатки журналов.
Локальный проверяемый пакет: `numerical-reports/native013-compact`.
Подробные журналы Windows: `.gpu-jobs/native013/r/autograd.log` и
`.gpu-jobs/native013/r/analytic.log` внутри разрешённого проектного каталога.
Сырых трасс не было создано.

## Проверка безопасного варианта после отказа

В справке **установленной версии** проверены остальные переключатели:
`--gpuctxsw=false` и `--isr=false` уже являются значениями по умолчанию;
`--wddm-additional-events` применяется только при явно включённом `--trace=wddm`,
которого в зарегистрированной команде нет. `--etw-provider` добавляет
пользовательские провайдеры, а не отключает обязательный провайдер CUDA.
Срез: `experiments/2026-10-18-nsys-etw-options.json`.
Оснований повторять ту же попытку под видом отключения уже выключенной
возможности не найдено. Это вывод для проверенной команды и текущих прав,
а не доказательство невозможности любого внешнего профилировщика.

Для полного профиля остаётся внешнее условие: возможность запуска трассы
с нужными правами в том же проектном каталоге. Это не основание обновлять Torch.
Независимая работа без этих прав возможна: отдельные синхронизированные
измерения на замороженных весах и холодного/тёплого предсказания. Они требуют
отдельного зарегистрированного режима очереди без Nsight и не заменяют
профиль ядер. Общие критерии TASK-21 не отмечались, defaults не менялись.
