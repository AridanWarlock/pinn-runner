## Проект и предпочтения пользователя

Репозиторий: https://github.com/AridanWarlock/pinn-runner.
Рабочая копия Mac: `/Users/user/Documents/ChatGPT/pinn_runner`.
Это одноразовый файловый решатель, не сервер. Внешний сервис запускает его
в изолированном Docker-контейнере; входы — `config.yaml` и `functions.py`.
`initial_conditions` задаются в функции постановки. `data.mat` не нужен
ни обучению, ни предсказанию; аналитическое решение в бенчмарках используется
только для независимой оценки. Обратную задачу восстановления коэффициентов
пока не решаем. Публичный `retrain` начинает новую оптимизацию из весов,
не продолжает автоматически историю Adam/L-BFGS.

Глобальные цели: 1D–3D, входные параметры семейства, пространственные поля
коэффициентов, читаемый расширяемый код. Большая часть инфраструктуры уже есть.
Текущий приоритет — точность/стоимость тепловых задач на декартовых
прямоугольниках, особенно точные условия Робина/Неймана, на текущих версиях.
Обновление библиотек отложено. Идею перехода к радиусу r пользователь отложил;
не возобновляй её автоматически.

Пользователь пришёл из типизированных языков: явные типы, Ruff и strict mypy,
небольшие понятные объекты вместо огромных методов. Обычный масштаб коммита —
законченный блок порядка 10 минут, не каждые несколько строк. Новая ветка
не нужна для каждого коммита: продолжаем тематическую `codex/robin-box`.
Не сохраняй legacy ради совместимости, если он больше не нужен, но доказывай
сохранение физического смысла изменений. Объясняй ключевые решения по-русски,
подробно раскрывай математику и Python по просьбе. Формулы — только отдельными
блоками `$$ ... $$`: встроенный синтаксис в интерфейсе не отображается.

## Архитектура и текущие переключатели

- `runner/settings.py`: строгая схема пользовательского YAML.
- `api.py`: `Coordinates`, `Equation`, описание `Problem`.
- `runner/problem.py`: `ProblemAdapter`, физические поля, коэффициенты и невязки.
  **`residuals()` возвращает и поля, и невязки. Для loss выбирать имена
  уравнений**, иначе случайно добавится штраф за значение температуры.
- `runner/factory.py`: сборка модели, данных и Trainer; разрешение политики
  конечного обратного прохода — отдельно в `runner/backward.py`.
- `PINNModule.forward`: физическое поле; `model_step`: функционал условий/PDE;
  `backward`: конечные градиенты весов; `predict_step` включает координатный
  граф, когда физическое преобразование требует производных потенциала.
- `training/refinement.py`: фиксированная цель и продолжаемая история
  L-BFGS в рамках стадии. Точки свежие как листья графа, значения фиксированы.
- `ConstraintPlan`, `BoxRobinInitial`, проекции и продолжения — отдельные
  объекты. Бенчмарки используют полиморфные `BenchmarkCase` и адаптеры.
- `benchmarks/convergence.py`: план/варианты, обучение со срезами и независимая
  оценка; `benchmark_time_to_quality.py` — CLI, без зашитого Дирихле 3D.

Текущие default: общие ограничения `soft`; для `hard_initial_robin`
проекция `robin_grouped`; продолжение `recursive`; `time_power: 0`;
**`backward: all` пока сохранён**. Явные варианты:

```yaml
training:
  constraints: hard_initial_robin
  hard_execution: robin_grouped
  hard_lifting: expanded
  backward: parameters
```

`backward: auto` уже реализован как явный выбор. Он выбирает `parameters`
только для `hard_initial_robin`, одного CPU/CUDA, `32-true`; иначе `all`.
Явный `parameters` требует поддерживаемую среду и разрешён для других
ограничений как эксперимент. В сохранённой модели `backward_mode` содержит
разрешённый режим, в YAML — запрошенный. **Не менять default до результата
всей заранее объявленной матрицы.**

Точные условия Робина: одно физическое поле, 1D–3D, постоянные коэффициенты
граничных операторов, ненулевой коэффициент нормальной производной на каждой
грани, совместимые гладкие данные. Полные смешанные Дирихле/Робин,
варьирующиеся входные семейства и `heat_flux` этим точным преобразованием
пока не поддержаны. Другие постановки имеют мягкий путь; не расширять
область применимости молча.

## Уже завершённые исследования

[Отчёт предыдущего блока](current-stack-study-2026-10-15.md): 18 обучений.
512→2048 точек улучшило позднюю ошибку относительно моды с 3,49/2,64%
до 1,28/1,40%, но память 244→924 МиБ. `time_power: 1` ухудшил обе модели
и не прошёл строгую PDE-проверку. Это изменение плотности функционала,
а не прозрачная замена координат.

Раскрытое продолжение дало около 21% выигрыша обучения на пяти состояниях,
но медианная общая ошибка +1,64%, последняя +6,93%: заранее заданный критерий
«не хуже» не выполнен. Поэтому `expanded` остаётся включаемым явно.
Прямой одномерный путь устранил первоначальную регрессию.

На 16 моделях сверены 23328 точек начального/последнего MAT-слоя и случайные точки:
максимальная разница с моделью 7,16e−7. Сдвига временной метки не обнаружено.
Формат MAT: координаты пространства отдельно, время отдельно, поле Ns×Nt.

Новое сокращение — только конечный градиент по весам, **не отключение
координатных производных внутри PDE**. `PINNModule.backward` сохраняет
стандартный путь Lightning; его же вызывает closure L-BFGS. Математика:
[parameter-backward.md](parameter-backward.md),
[подробный вывод](parameter-backward-math.md).
Прогретые графы Нейман/Робин/смешанные 3D, оба lifting: градиенты побитово
совпали. Полное построение невязки+backward быстрее примерно 20–22% для
recursive и 11–17% для expanded. Первые две полные пары тоже имеют одинаковые
метрики. Первая пара train376,24→300,76 с; пока не объявлять всю матрицу принятой.

В холодном сравнении была разница 1,8e−8; контрольный cold-all отличался
от собственного warm-all до 1,36e−7. Добавлен симметричный прогрев и
проверка самоповторяемости, **с нулевыми допусками и без смягчения порогов качества**.
Конкретная внутренняя причина первого вызова не установлена.

Профилировщик Windows: `supported_activities` содержит только CPU.
Есть CUDA-времена таблицы резервного пути, но нет CUDA-ядер в Chrome JSON.
Это не означает нулевые запуски/копирования. Полное разложение по ядрам
не получено; TASK-21 поэтому нельзя объявить полностью завершённой.

## Новый спектральный разбор и ограничения

[neumann-error-spectrum.md](neumann-error-spectrum.md), JSON/PNG в experiments.
Шесть старых MAT проанализированы на Mac без нового обучения/предсказания.
Простой тезис «в поздней ошибке доминируют медленные формы» не подтвердился
для равномерных выборок: быстрые формы дают 54–84% дискретной энергии.
В неудачной поздней плотности постоянная форма даёт 42–51%.
Это грубая сетка 9³ и трапециевидные веса, не непрерывный сертификат.
Полная дискретная косинусная система проверяет равенство Парсеваля;
неразрешённые частоты могут накладываться. Старые gates не заменяются.

Подготовлено подтверждение на независимых квадратурах Гаусса 13/17:
`benchmark_neumann_projection.py` + `benchmarks/neumann_projection.py`.
Проецируются все формы не быстрее исходной, остальное — быстрый остаток.
Проверяются матрица скалярных произведений, нормы и восстановление энергии.
Численные GPU-результаты этого подтверждения пока **не получены**.
Общий загрузчик бенчмарков теперь умеет переопределять сохранённый CUDA-конфиг
на CPU до построения Trainer. Маленькая проверка на Mac не считается CUDA-тестом.
