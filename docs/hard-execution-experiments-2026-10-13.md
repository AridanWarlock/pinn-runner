# Hard: первый эксперимент с полиномом и стоимостью исполнения

2026-10-13. Это первый блок heat-плана, не завершение TASK-21 или интеграции
всех BC. Измерения выполнены на Windows RTX 4070 Ti, Torch 2.1.0+cu118,
FP32, CUDA matmul/cuDNN TF32 выключены. Нового обучения не проводилось.

## Математика и границы оптимизации

Текущая конструкция остаётся u = g + τ B N, где
B = ∏ 4ξᵢ(1−ξᵢ), ξᵢ = (xᵢ−aᵢ)/(bᵢ−aᵢ), τ = (t−t₀)/(t₁−t₀).
Новая операция вычисляет один фактор через addcmul(ξ,ξ,ξ,value=−1):
ξ−ξ² = ξ(1−ξ). Это одинаковый полином в вещественной арифметике.
Первая производная по ξ — 1−2ξ, вторая — −2; масштабные множители
по физической координате — 1/L и 1/L² соответственно.

FP32 округление не обязано совпадать: выполняется другая последовательность
операций. Near-boundary значения проверяются абсолютными допусками, поскольку
относительная ошибка около нулей неустойчива. Не делим на B, τ или их факторы.
Значения на точных концах ξ=0/1 остаются нулевыми.

Операция используется только при fused_predict и выключенных градиентах.
При включённых градиентах остаётся прежний код, в том числе для координатных
производных, PDE loss и parameter gradients. Оптимизатор, пространство моделей,
функции пользователя, коэффициенты и checkpoint-веса не изменены. Это не новый
способ встраивания BC. По умолчанию остаётся eager; общий constraints default
в этом блоке не менялся.

## Предварительный CUDA-прототип: важный отрицательный результат

Диагностический прототип использовал 3D sin-product IC, сеть Tanh 4→32→32→32→1,
seed 1234, фиксированные случайные входы, residual u_t−0.05Δu и backward.
Замер — 10 warmup, медиана пяти серий по 50 вызовов, sync на границах серий.
Второй замер убрал преобразование loss в Python float из каждого шага.
Это синтетический microbenchmark, не обучение solver и не time-to-quality.

| Batch | B eager, ms | B candidate, ms | residual+backward eager, ms | candidate, ms |
| --- | ---: | ---: | ---: | ---: |
| 128 | 0.1522 | 0.1066 | 9.7557 | 10.0597 |
| 2048 | 0.1590 | 0.1056 | 9.7623 | 10.0519 |
| 17 | 0.1622 | 0.1100 | 9.5884 | 9.9354 |

Множитель быстрее приблизительно на треть, но полный residual+backward медленнее
на 3–4%. Максимальная разница parameter gradients 1.49e−8–5.96e−8.
Сокращение forward-операций не гарантирует удешевления AD графа. Именно поэтому
candidate не используется при обучении.

Profiler был отделён от timing, но не зарегистрировал CUDA events на этой
конфигурации. Нулевой счётчик не означает отсутствие kernels; достоверной
декомпозиции CUDA kernels/derivatives/optimizer пока нет. Верхняя граница
ускорения всего обучения по этому профилю не установлена. Точные синтетические
числа — предварительная диагностика; основной воспроизводимый acceptance ниже.

## Решение и дальнейшая работа

Сохраняем небольшой opt-in fused_predict. Не включаем default: проверенный
выигрыш warm inference не переносится на файловый запуск, а при обучении этот
полином в прототипе замедлял backward. Подтверждённого ускорения обучения до
заданной точности в этом блоке нет.

Не проверены: ускорение аналитической сборкой heat derivatives, кеш обучающих
производных, аффинная свёртка сети, compile/graphs, полный profiler, иные BC.
TASK-21 остаётся In Progress. Интеграция расширенных heat BC выделена в
TASK-22 (контракт), TASK-23 (ненулевой Dirichlet), TASK-24 (Neumann/Robin).

Проверки: полный CPU check — Ruff/format/strict mypy + 251 tests (91.49 s).
После изменения только harness — быстрый check: 232 passed, 19 e2e deselected,
50 файлов strict mypy. Профильные hard CPU: 12 passed. Windows hard + hardware:
19 passed (10.84 s). Дополнительно шесть публичных CUDA predict и сравнение MAT.
Последний typed-only фикс harness не меняет вычисления, cold run проверен на 49a1650.
