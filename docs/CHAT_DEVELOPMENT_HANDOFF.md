## Проект и предпочтения

Репозиторий: https://github.com/AridanWarlock/pinn-runner.
Mac: `/Users/user/Documents/ChatGPT/pinn_runner`, ветка `codex/robin-box`.
Это одноразовый файловый решатель в Docker, не сервер. Входы — `config.yaml`
и `functions.py`; начальное условие обязательно и задаётся через `Problem(initial=...)`. `data.mat`

Пользователь пришёл из типизированных языков: явные типы, Ruff, strict mypy,

## Текущие настройки и архитектура

По умолчанию общие ограничения `soft`; внутри `hard_initial_robin` —
`robin_grouped`, `hard_lifting: recursive`, `time_power: 0`.
**Новое значение по умолчанию — `training.backward: auto`**: `parameters` только для
`hard_initial_robin` на одном CPU/CUDA с `32-true`, иначе `all`.
Явный `all` сохраняет контроль. Явный `parameters` разрешён на одном CPU/CUDA
с FP32 и для других постановок как дополнительная опция.
Бенчмарки сохраняют контроль `all` по умолчанию независимо от решателя.

`parameters` здесь — обучаемые веса, не входные параметры вроде κ.
Внутренние координатные производные PDE сохраняются. Только конечный обратный
проход не накапливает `.grad` координат, которыми оптимизатор не управляет.
Один `PINNModule.backward` используется Adam и L-BFGS, явные `inputs` имеют
приоритет. Режим не меняет физическую сигнатуру весов.

Основные точки входа:

- `runner/settings.py`, `runner/backward.py`: схема и разрешение политики.
- `runner/problem.py`: `ProblemAdapter`. **`residuals()` возвращает поля вместе
  с невязками; для функционала выбирай имена уравнений**, иначе добавится штраф за u.
- `runner/factory.py`: сборка модели, данных и Trainer.
- `PINNModule.forward`: физическое поле; `model_step`: функционал;
  `predict_step`: включает координатный граф, когда преобразованию нужны производные.
- `training/refinement.py`: фиксированная цель L-BFGS и непрерывная история
  оптимизатора в пределах стадии; значения точек фиксированы, листья графа свежие.
- Проекции/продолжения и `ConstraintPlan` — отдельные объекты.
  Бенчмарки используют полиморфные `BenchmarkCase`.
- `benchmarks/convergence.py`: план, обучение со срезами, независимая оценка.
  Аналитический ответ нельзя смотреть до окончания всех шагов конкретного опыта.

`hard_lifting: expanded` остаётся дополнительной опцией. Прежняя матрица пяти
состояний дала ускорение около 21%, но медианная последняя ошибка ухудшилась
на 6,93%, общая — на 1,64%. Критерий «медианы не хуже» не выполнен. Два новых
сравнения all/parameters на expanded этого решения не отменяют.

## Опытное сокращение графа производных
