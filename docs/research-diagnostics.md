# TASK-29: диагностика и целостность исследовательских результатов

## Требования

Следующий агент должен понимать состояние задачи, не перечитывая большой журнал
или вложенный научный отчёт. Сохраняются математические критерии TASK-27/28;
новый слой отвечает за наблюдаемость и целостность файлов, не за изменение PDE.

1. Диагностика локальной копии не проверяет Windows-PID на Mac. Она показывает
   сохранённое состояние отдельно от фактически проверенного владельца.
2. Удалённая диагностика использует прежний защищённый PowerShell/SSH-транспорт.
   Не создаёт процессы обучения, не меняет состояние задачи и не повторяет запуск.
3. По умолчанию журналы не читаются. По явному выбору возвращается только
   ограниченный хвост `run.log` или `launcher.log`. Бюджет ограничивает чтение
   файла **до** загрузки и декодирования. Произвольные пути запрещены.
4. Повреждённые/отсутствующие метаданные и неизвестный владелец дают `unknown`,
   а не предположение об успехе или завершении. Структурированные коды причин
   позволяют машине выбрать следующий диагностический шаг.
5. Однозначный отказ до создания процесса сохраняется как `failed`. Ошибка
   после возможного создания процесса остаётся неопределённостью; повтор запрещён.
6. Пакет результатов имеет завершающую запись, опубликованную последней.
   Частичная запись, изменение JSON или CSV обнаруживаются перед сравнением.
   Уже существующий пакет не перезаписывается.
7. Проверки выполняются поддельными процессами/файлами на Mac и чтением прежних
   завершённых Windows-задач. Новые обучения для этого блока не нужны.

## Команды

```sh
python3 scripts/research.py diagnose --remote --job-id q28-tiny
python3 scripts/research.py diagnose --remote --job-id q28-tiny \
  --log run --lines 10 --max-bytes 2048
python3 scripts/research.py diagnose --root /path/to/copied-job \
  --log launcher --lines 20 --max-bytes 4096
```

Результат — `contract: 1`, `kind: research-diagnosis`, короткий статус,
`live_owner_check`, наличие запроса отмены и список доступных журналов.
`--log` добавляет текст хвоста, прочитанные/полные байты и флаг `truncated`.
Успех команды означает успешную диагностику, не успешность обучения.

По умолчанию: 40 строк и 4096 байтов. Максимум: 100 строк и 16384 байта.
Декодирование UTF-8 заменяет неполную/некорректную последовательность; ограничение
относится к входным байтам. Размер JSON в байтах может быть больше из-за Unicode
и экранирования. Метаданные читаются не более 64 KiB; выбранные текстовые поля
ограничены 500 символами, произвольные вложенные значения не выводятся.

`run` содержит вывод исполнительной части, `launcher` — ранние ошибки рабочего
процесса. Пустой журнал не означает успех. Если файла нет, возвращается короткая
ошибка этого чтения; остальные сведения остаются доступными.

## Причины неопределённости и отказа

- `ownership_not_checked`: локальная копия; текущий Windows-владелец не проверялся.
- `metadata_unreadable`: файл отсутствует, повреждён, слишком велик или его
  структура не позволяет проверить владельца/состояние.
- `launch_uncertain`: отметка запуска есть, подтверждённого владельца нет.
- `worker_unverifiable`: прежний рабочий процесс не подтверждается по PID и
  времени создания. Не завершать другой процесс с повторно использованным PID.
- `launch_rejected`: известный отказ до создания процесса. Сохраняются `failed`,
  краткая ошибка и время. Этот же ID не запускается повторно.

Обрыв SSH после успешного создания процесса и ошибка записи его метаданных
принципиально отличаются от отказа `CreateProcess`. Диагностика не делает
автоматического восстановления, удаления файлов или повышения привилегий.

## Публикация пакета результатов

`collect` создаёт новую папку и пишет `evidence.json`, `final.csv`, `snapshots.csv`.
Затем вычисляет SHA-256 их байтов и последним публикует `bundle.json` через
временный файл и замену. `compare` проверяет наличие этой записи, её контракт,
точный список файлов и все контрольные суммы. JSON разбирается из тех же байтов,
чья сумма была проверена. Символические ссылки наружу не принимаются.

Если запись оборвалась, папка остаётся для диагностики без завершающей записи;
она не считается опубликованным пакетом. Повторный сбор направляется в новую
папку. Автоматической очистки или перезаписи нет. Ранние пакеты TASK-27/28 без
`bundle.json` нужно собрать заново из исходных отчётов, без повторного обучения.
Нельзя вручную дописывать маркер к неизвестным повреждённым данным.

Контрольная сумма устанавливает целостность относительно завершающей записи,
не авторство и не математическую истинность. Пользователь с правами на все файлы
может изменить и данные, и запись; это не криптографическая подпись.

## Математические инварианты

Не менялись невязка PDE, пространство функций сети, производные, оптимизаторы,
критерии точности и два соседних успешных состояния. После файловых проверок
сравнение заново вычисляет прежние научные критерии. Ни целый пакет, ни `completed`,
ни отсутствие текста ошибки в журнале не доказывают достижения целевой точности.
Условия применимости математических преобразований сохраняются в
[контексте агента](agent-research-context.md), полный рабочий API —
[в основном контракте](research-workflow-api.md).
