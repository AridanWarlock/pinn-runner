# Отчёт об уборке кода

Исторический отчёт. Текущие интерфейсы описаны в [API.md](API.md) и
[architecture.md](architecture.md); часть перечисленного legacy уже удалена.

Работа выполнена в ветке `codex/code-hygiene`. Это широкая механическая уборка
и уточнение интерфейсов, а не реализация нового математического режима.

## Что изменилось

1. Привёл основной пакет, runner и поддерживаемые тесты к единому форматированию
   Ruff: длина строки 99, порядок импортов, удаление неиспользуемых импортов.
   Заменил wildcard-импорты в публичных точках пакета явными импортами и `__all__`.
   Проверил, что существующие публичные атрибуты четырёх точек входа сохранились.
2. Удалил перекрытый повторным определением метод `on_train_batch_start`,
   неиспользуемые присваивания и неработающий пример запуска сетей без обязательных
   аргументов. В графиках `except Exception` позволяет прерывать процесс через
   Ctrl+C: раньше голый `except` мог перехватывать такое прерывание.
3. Вынес общие типы в `pinnstorch/contracts.py`: массивы, результаты модели,
   batch, функции начальных условий, фабрики оптимизаторов и словари callbacks.
   Уточнил аннотации в сетях, загрузчике, численных функциях и runner.
4. Добавил строгую проверку mypy для восьми модулей. В частности, оптимизатор
   при создании модели описан как фабрика, которая создаёт Optimizer, а не уже
   созданный объект; optional-поля допускают `None` там, где это происходит
   в действительности. Batch содержит список пространственных тензоров,
   тензор времени и словарь целей, а не три одинаковых тензора.
5. Добавил ясные ошибки для конфигурации `domain`, которая не является mapping,
   и файла пользовательских функций, для которого Python не может создать loader.
6. Добавил `scripts/check.py`: одна команда проверяет lint, формат, типы и тесты.
   Убрал конфликтующие Python-инструменты из pre-commit и оставил там те же
   Ruff/mypy. Старые upstream-тесты перенёс вместе с fixtures в `tests/legacy`;
   обычный pytest теперь запускает поддерживаемый набор без специальных обходов.

## Как читать новые Python-типы

`TypeAlias` даёт имя существующему типу, не создавая дополнительный объект-обёртку.
Например, `TensorOutputs` означает словарь с именами полей и тензорами значений.

`TypedDict` описывает структуру обычного словаря. Для `UserFunctions` checker
знает обязательные `pde_fn` и `initial_conditions`, а `NotRequired` обозначает
необязательные ключи. Это не заменяет проверку загруженного пользовательского кода.

`Protocol` похож на интерфейс из типизированных языков, но реализовать его можно
без явного наследования: достаточно иметь совместимые методы. Так загрузчик
зависит от методов dataset, а не от конкретного класса.

`Callable[..., Optimizer]` описывает вызываемую фабрику с пока динамическими
аргументами. Многоточие не проверяет сигнатуру аргументов. Аналогично callbacks
PDE пока допускают разное число координат; это ещё не полная типизация 2D/3D API.

`cast` лишь сообщает mypy тип значения, ничего не преобразуя во время выполнения.
Использую его на границах динамических библиотек, например OmegaConf и nn.Module.
Проверки формы и конечности входных массивов остаются runtime-проверками.

`TYPE_CHECKING` и отложенные аннотации позволяют использовать типы без лишних
импортов при выполнении. Это важно для лёгкого импорта CLI и численных тестов.

## Проверки и пределы результата

Локально прошли Ruff, проверка форматирования, строгий mypy для восьми файлов и
52 CPU-теста. Дополнительно сравнил старую и новую реализации сетей при одинаковых
весах: девять вариантов FCN/NetHFM для 1D/2D/3D дали точно одинаковые выходы;
у FCN также совпали проверенные вторые производные. Это отдельная локальная
проверка механического изменения, не новый тест с доказательством сходимости.

CUDA, AMP и JIT на RTX здесь не проверялись. Динамические части Lightning и
Runge–Kutta не входят целиком в строгую область mypy; местами `Any` сохраняется
явно. Старые тесты не объявлены исправленными. Незавершённый RectangularPrism
и логика разбиения batches не исправлялись в этой задаче.

Новые возможности 2D/3D, варьирующиеся параметры и обратные задачи не добавлены.
Контракт с обязательными начальными условиями и без `data.mat` для обучения
и предсказания сохраняется. Инструкции по запуску: [development.md](development.md).
