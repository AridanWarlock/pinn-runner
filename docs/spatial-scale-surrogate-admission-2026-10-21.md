# TASK-39.3: численный допуск пространственного коэффициента

Физический оператор и его производные для общей сети с входным масштабом a
прошли CPU и CUDA-контроли. **Обучения качества этого семейства не было.**
TASK-39.3 остаётся In Progress; численный допуск не является приёмкой суррогата.

Постановка, полный вывод, нормали, баланс и перспективные цели:
[протокол](spatial-scale-surrogate-protocol-2026-10-21.md).
Коэффициент k(x)=a[1+2x(1−x)], начальное поле 4x(1−x), источник нулевой.
При фиксированной форме один a описывает всю функцию, а не локальное значение
в произвольном профиле.

## Источники и фактические проверки

- Исходники `bc2b8eefeaf76e4c1213feab6d7cfbc971d0735b`.
- Протокол CUDA `88fb50f82bbda96fe5300ba063597f602a58e1bb`:
  [машинный файл](experiments/2026-10-21-spatial-scale-numerics-protocol.json).
- Полный CPU-набор `scripts/check.py --full`: Ruff, format, strict mypy,
  **1030 тестов**, без исключения файловых сценариев.
- Профильный CPU-набор отдельно: шесть тестов, четыре реальные сети с 2273
  параметрами, состояния 11/29, FP32/FP64 и два точных поля.
- CUDA `cs392n1021`: те же шесть тестов, **6/6**, штатные collect/compare,
  `comparison_passed=true`. RTX 4070 Ti, Torch 2.1.0+cu118, CUDA 11.8,
  FP32 по умолчанию, TF32 выключен; FP64 явно задан соответствующими тестами.
- Во всех этих численных проверках **ноль шагов оптимизатора**;
  четыре центральные конечные разности по полному направлению весов FP64,
  сопоставление всех градиентов, смешивание и разбиение партий, IC/BC,
  неизменность состояния сети. Изменения весов для конечных разностей обратимы
  и проверены восстановлением исходного отпечатка.

[Компактный пакет](experiments/2026-10-21-spatial-scale-evidence/numerics)
сохранён для независимой повторной проверки:

```sh
python3 scripts/research.py compare --bundle docs/experiments/2026-10-21-spatial-scale-evidence/numerics
```

Физическая дивергенция сопоставлена с раскрытым kTxx+kxTx и всеми градиентами
по весам. Отрицательные контроли обнаружили потерю kxTx и ошибочное добавление
производной по a в пространственный лапласиан. На точном поле неправильная
невязка дополнительно совпала с независимо выведенной формулой.

Отдельные [16 аналитических CPU-контролей](experiments/2026-10-21-spatial-scale-analytic-controls.csv)
проверили интегральное теплосодержание, выходящие потоки и уравнение:
максимальная невязка 4.45e-16, нарушение баланса 4.45e-16.
Во всех сочетаниях найдена точка с ошибкой неверного оператора не менее 0.09957.
Это проверка математики и источника, без обучения.

## Что осталось до научного результата

1. Зарегистрировать эту семью в отдельной оценке гипотез масштаба a,
   сохранив непрерывную LHS-выборку и раздельные метрики девяти a.
2. Провести файловый допуск фактического источника: загрузка, новые a,
   точное восстановление весов и отказ за пределами диапазона.
3. Опубликовать исполняемый протокол с ревизией оценщика и прежними уже
   выбранными целями; затем три общие модели в бюджете 500 Adam + 500 L-BFGS.
4. Собрать и сравнить качество и полную стоимость, сохранив все исходы.

Нельзя автоматически запускать постоянный случай под новым названием:
у пространственного источника другое начальное поле и другой смысл параметра.
Также нельзя объявлять проверку свободной формы k(x): здесь форма фиксирована,
а точный свободный выход одномодового решения может не зависеть от x.

Для будущего интерфейса дополнительно сохранён
[контрпример локального значения коэффициента](surrogate-function-input.md).
Он объясняет необходимость кода всей функции в TASK-39.4, не вводя этот API сейчас.

## Навигация для следующего блока

Чтобы не восстанавливать всю исследовательскую инфраструктуру заново:

- `benchmarks/catalog.py` и `benchmarks/cases.py`: новый случай качества
  должен иметь параметр a и собственный аналитический эталон 4x(1−x)exp(−12at).
  Сейчас в каталоге обучения его намеренно нет; источник уже готов и проверен.
- `benchmarks/surrogate_quality.py`: прежний оценщик жёстко задаёт синус и
  постоянный k. Его нельзя применить к новому источнику без отдельного эталона
  и идентичности оценки. Сохранить прежнюю интерпретацию постоянного случая.
- `research_tools/schema.py`, `planning.py`, `surrogate_evidence.py`: новую
  идентичность связать только с пространственным случаем, сохранить девять a,
  отрицательный контроль, максимумы и проверку неизменности весов. Не менять
  задним числом опубликованные матрицы и пакеты постоянного k.
- `scripts/benchmark_time_to_quality.py` и `benchmarks/convergence_processes.py`:
  все цели, включая отклик на коэффициент, должны пройти через настоящий дочерний
  CLI. Проверить это сквозным тестом, а не только локальной передачей словаря.
- Файловый допуск должен использовать именно новый источник и входы x/a/t,
  предсказывать новые a=0.1/0.2, сверять прямое воспроизведение сохранённых весов,
  проверять восстановление с ничтожным шагом и отказ для a=0.3. Постоянный
  файловый тест подтверждает механику, но не заменяет этот новый сценарий.

После этого закрепить новую ревизию обучения и отдельный commit машинного
протокола, затем применить обычные plan/submit/collect/compare. Нового транспорта,
GPU-блокировки или универсального интерфейса функций для этой ступени не нужно.
