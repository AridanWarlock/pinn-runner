# План: hard constraints для теплопроводности в прямоугольной области

Дата: 2026-10-13. Статус: проект плана, реализация приостановлена.

## Область задачи и математический контракт

Область Ω = ∏[aᵢ,bᵢ], пространственная размерность d = 1, 2 или 3,
время [t₀,t₁]. Уравнение:

    u_t − div(K grad u) = f,   u(x,t₀) = g(x).

Первая очередь: положительный постоянный скаляр K = κI. Затем гладкий
пространственно меняющийся κ(x); тензорный K и скачки коэффициента — отдельное
расширение. Не заменять div(κ grad u) на κ Δu при переменном κ.

На каждой грани задаётся одно условие: температура, внешняя нормальная
производная либо физический внешний поток q·n, где q = −K grad u.
Для Робина фиксируем соглашение a u + b q·n = h. Условие с производной
нужно явно отличать от условия с потоком: их коэффициенты и знаки различаются.
На нижней грани n = −eᵢ, на верхней n = +eᵢ.

Не использовать аналитическое решение в обучении. Не менять PDE, единицы,
точность вычислений, оптимизатор или выборку под видом ускорения hard.
Ожидаемые гарантии отдельно: точные IC/BC, приблизительное выполнение PDE.

## 1. Зафиксировать контроль и измерить текущий hard

Контроль: текущий HardBoxInitial, eager FP32, TF32 выключен, текущая стадия
Adam → L-BFGS. Закрепить SHA, конфиг, версии, seed и checkpoint; сохранять
requested/effective стратегии. Сопоставлять результаты с существующими отчётами
accuracy-experiments-2026-10-13.md и lbfgs-experiments-2026-10-13.md.

Profiler отдельно от timing: сеть и нормализация входов, начальное поле,
множитель hard, координатные производные, backward, optimizer/closure,
запуски CUDA kernels, выделения памяти, копирования и синхронизации.
Timing: холодный запуск контейнерного сценария, подготовка, шаг Adam,
closure L-BFGS, warm inference и файловый predict. Пачки 128, 2048 и неполная.

## 2. Удешевить текущую конструкцию без изменения её смысла

Для ξᵢ = (xᵢ−aᵢ)/Lᵢ, Lᵢ = bᵢ−aᵢ, τ = (t−t₀)/T:

    B = ∏ 4ξᵢ(1−ξᵢ),   u = g + τ B N.
    u_t = B N/T + τ B N_t.
    u_i = g_i + τ(B_i N + B N_i).
    u_ii = g_ii + τ(B_ii N + 2 B_i N_i + B N_ii).

Здесь B_i и B_ii — производные полного произведения B; производные отдельного
фактора равны 4(1−2ξᵢ)/Lᵢ и −8/Lᵢ². Вычислять произведения без деления
на отдельный фактор: на границе он равен нулю. Не делить residual на τB.

Кандидаты в порядке доказуемости и измеренного эффекта:

- Подготовить постоянные масштабы/геометрию один раз; сократить временные
  тензоры и повторные операции. Проверить округления из-за замены деления.
- Кешировать g и B на фиксированной сетке predict. При обучении кеш допустим
  только с восстановлением всех необходимых производных, включая градиенты
  по обучаемым величинам; простое detach запрещено.
- Для подготовленной копии модели predict свернуть аффинную нормализацию
  z = Ax+c в первый Linear: W' = WA, b' = Wc+b. Обучаемую модель и состояние
  Adam/L-BFGS не перепараметризовать этим способом.
- Если profiler показывает существенный overhead производных hard, испытать
  приведённое правило произведения для heat residual вместо повторного AD
  всей композиции. Производные g получать из пользовательского IC через AD;
  ручная перепись functions.py не требуется. Контроль — полный eager AD.
- Fusion/CUDA graphs исследовать после локальных упрощений. Compile только
  после проверки поддержки текущего Windows/CUDA стека; обновление библиотек
  не входит в этот блок. Холодная подготовка должна окупаться за один запуск.

Инвалидация кеша: координаты и resampling, границы и интервал времени,
IC/коэффициенты и параметры, dtype/device, рецепт модели. Нельзя сохранять
граф с весами между optimizer steps. При изменении κ(x) включить grad κ
в проверку residual. Безразмеризация — отдельная гипотеза кондиционирования,
а не прозрачное ускорение вычислений.

## 3. Интеграция hard как явной стратегии

Создать HeatProblem/BoundarySpecification, PreparedConstraint и компилятор
ConstraintPlan: валидация один раз, горячий путь только тензорные операции.
Отделить математическую конструкцию от backend её исполнения.

Каждая стратегия сообщает: точные ограничения, оставшиеся loss, предпосылки,
выходные физические/вспомогательные поля, требуемые производные и signature.
Checkpoint хранит разрешённую стратегию и математический рецепт. Проверить
save/load, predict и fine-tune; подготовленная inference-копия не меняет
канонические веса checkpoint.

Проект пользовательского API (ещё не поддерживается):

    training:
      constraints:
        mode: hard       # либо soft
        formulation: temperature  # экспериментально: mixed_flux
      execution:
        hard: eager     # либо проверенный prepared backend

Для heat-профиля после численного подтверждения default — прямой hard.
Явный soft остаётся доступен. Неподдержанный hard даёт объяснение и ошибку,
без молчаливого перехода на soft. До достижения покрытия не объявлять hard
универсальным default для остальных PDE или всех граничных условий.

## 4. Ненулевые и зависящие от времени условия Дирихле

Сначала построить подъём A(x,t), удовлетворяющий данным на всех гранях
через тензорную/трансфинитную интерполяцию с поправками на пересечения.
Для B, исчезающего на всех гранях, использовать:

    u = A(x,t) + [g(x) − A(x,t₀)] + τ B N.

При совместимости g с BC в t₀ квадратная скобка равна нулю на гранях:
получаем точные IC и BC одновременно. Она не обязана быть нулевой внутри.
Угловые/рёберные данные Дирихле должны совпадать; противоречие отклоняем.
Численная проверка на точках не является доказательством совместимости
произвольных пользовательских функций; документировать её пределы.

## 5. Прямой hard для Неймана, Робина и смешанных граней

Начать с одной плоской грани. r — расстояние внутрь, s — касательные
координаты. Для a u + b ∂ₙu = h при b ≠ 0:

    u(s,r,t) = F(s,t) + r [aF(s,t)−h(s,t)]/b + r²H(s,r,t).

При r=0 получаем u=F и ∂ₙu=(h−aF)/b. Не фиксируем свободное граничное
значение F. Для скалярного потока q·n = −κ∂ₙu изменить коэффициент линейного
члена согласно соглашению о потоке. b=0 обрабатывается как Дирихле,
без деления на ноль; почти вырожденные коэффициенты требуют масштабирования.

Дальше: парные грани одной оси через полиномиальные/Hermite-конструкции,
затем композиция по осям. Для каждой композиции доказать сохранение ранее
заданных условий и отсутствие лишних ограничений на свободные следы.
Общие пространственно меняющиеся Robin-коэффициенты не считать автоматически
покрытыми простым тензорным произведением: операторы могут не коммутировать.

В углу применять ограничения каждой грани с её нормалью, а не усреднённую
нормаль. Проверять существование совместимого гладкого значения/градиента
и граничных следов; не требовать равенства потоков разных граней. Условия
смешанного типа могут порождать негладкое решение даже на прямоугольнике.
Исключение углов из sampling не устраняет эту математическую проблему.

Для совместимых данных добавить IC, проверив не только g, но и его нормальные
производные/потоки при t₀. Не переносить формулу этапа 4 на Робина/Неймана
без доказательства: поправка g−A(t₀) может нарушать текущий граничный оператор.
Этап завершается отдельными поддержанными классами условий; общий hard
для любых комбинаций не обещаем до доказательства конструкции.

## 6. Отдельный эксперимент: смешанная модель температуры и потока

    q = −κ grad u,
    u_t + div q = f.

Сеть выдаёт u и d компонент q. Loss содержит residual баланса и residual
согласования q+κ grad u. Все координатные производные первого порядка.
BC a u + b n·q = h становится алгебраическим: его можно обеспечить проекцией
на допустимое подпространство. Объединение граней и пересечений требует
отдельной конструкции; последовательные проекции могут нарушать друг друга.

Hard гарантирует BC для предсказанного q, но не автоматически для потока
−κ grad u. Измерять оба, особенно на границах; loss согласования проверять
на границах и независимых внутренних точках. Исходная и смешанная задачи
эквивалентны только при выполнении связи. Масштабировать residual по единицам.
Это изменение представления и оптимизационной задачи, отдельный toggle,
не «математически прозрачная» замена текущего backend и не default заранее.

## 7. Проверки и критерии принятия

Математические CPU-тесты float64 и FP32: поле, первые/вторые производные,
heat residual и градиенты по весам. 1D/2D/3D, смещённые и вытянутые области,
неединичный временной интервал, все грани/рёбра/углы, близкие к границе точки.
Для прозрачной оптимизации сравнение на одинаковых весах и координатах;
допуски заранее обосновать через масштаб производных и dtype.

Численные CUDA-сценарии с аналитическим решением только для оценки:

1. Затухающая синусоидальная мода: нулевой Дирихле, 1D–3D.
2. Затухающая косинусоидальная мода: нулевой Нейман; контролировать сохранение
   среднего при f=0 и нулевом потоке. Это эволюционная задача с заданным IC,
   не стационарная задача Неймана с неопределённой добавочной константой.
3. Manufactured solution со временем и ненулевыми Дирихле/Нейманом/Робином
   на разных гранях: f и BC получают аналитически, но u_exact не даётся сети.

Первое screening — два seed; подтверждение изменений обучения — пять
фиксированных seed: 1234, 4321, 19, 2026, 73. Одинаковая выборка/бюджеты;
Adam и Adam→L-BFGS сравнивать отдельно. Для чистого inference fast path
переобучение не требуется: используются одни и те же checkpoints.

Метрики: общий/последний/худший временной L2; абсолютные RMSE/max, поскольку
относительная ошибка неустойчива при затухании; PDE holdout, IC, BC по каждой
грани, ошибки рядом с углами, баланс энергии. Для mixed — согласование q
и −κ grad u. Отдельно число closure, посещений PDE-точек и wall time.

Time-to-quality: заранее объявить численные пороги и фиксированный график
контрольных checkpoints; время проверки учитывать отдельно и в общем времени.
Analytic validation не участвует в loss/подборе лучшего seed. Для устойчивого
достижения требовать два последовательных контрольных checkpoint в пределах
порогов; фиксировать дискретность измерения. Не прошедший пороги запуск —
неуспех, а не исключённый timing. Также сравнить качество при равном wall time.

Performance default: повторяемая экономия cold end-to-end ≥10% на значимых
профилях, отсутствие нарушения численных gates и согласованный бюджет памяти.
Более медленный backend, полезный только в отдельных режимах, оставить opt-in.
У hard нет гарантированного универсального выигрыша или предела точности.

Mac: быстрый check и профильные тесты по блокам; полный check при сквозных
контрактах/завершении. Windows RTX 4070 Ti: производные, train/predict/checkpoint
и длительная матрица только через SSH в C:\Projects\pinn-runner. CUDA не
подменяется Mac-тестами. Обновления Torch/CUDA — вне этого плана.

## Порядок поставки

1. Profiling текущего hard + прозрачное упрощение с доказательствами.
2. ConstraintPlan, явный soft и канонический checkpoint-контракт.
3. Hard IC + ненулевой Дирихле с совместимостью пересечений.
4. Нейман/Робин: одна грань → 1D пары → подтверждённые 2D/3D сочетания.
5. Mixed flux как отдельный эксперимент первого порядка.
6. Матрица точности/времени, решение о defaults, документация поддержанных BC.
