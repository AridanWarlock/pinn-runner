# TASK-21: полный запуск публичного предсказания

## Вопрос и фиксированная область

Есть ли регрессия полного времени публичного `predict`, когда одинаковая
сохранённая модель полинома3D исполняется с eager или neumann_analytic?
Различающая ветвь производных при предсказании не выполняется, поэтому
ускорение не ожидается; проверяется сохранение стоимости/результата.
Это последний недостающий режим измерения уже поставленного правила,
не новый fast path. Обучения и шагов оптимизатора нет.

Источник: существующая eager-модель analytic011/полином3D/seed19/lb-600,
веса `85f2994d9132bd3e2c4d7eb32f7959d90db4c6afd36ae703ac31ff8406353d83`,
конфигурация `8c09efd14cf09a0ad4dc0cf8ecadee880180d620b6952604412887f28a111ed2`.
Код и машинный протокол contract8 публикуются раздельными SHA до запуска.
RTX4070Ti, Torch2.1.0+cu118, CUDA11.8, FP32/TF32 off.

## Контейнер модели без обучения

Сырые `.pt` из исследования содержат state_dict, а публичный reader требует
также физические метаданные. Это нельзя исправить переименованием файла.
Из исходной конфигурации/Problem строится тот же объект; исходные тензоры
строго загружаются, затем сохраняются вместе с `model.hparams` в отдельный
контейнер для предсказания. Все тензоры сравниваются точно с исходными.
Исходный файл/конфигурация проверяются по SHA до/после и не переписываются.
История оптимизатора в контейнер не добавляется и не заявляется восстановленной.

До GPU проверен реальный CPU-файловый путь:
[сценарий](experiments/2026-10-18-public-checkpoint-preflight.py),
[результат](experiments/2026-10-18-public-checkpoint-preflight.json).
Сырой state_dict отвергнут, контейнер принят. Заданный выход последнего Linear
позволил проверить известное физическое поле Q+tau/4 на64×3 значениях,
максимальное отличие1,772e-7. Обучения не было; это не Windows timing.

Упаковка исследовательского состояния выполняется один раз вне часов
публичного predict: обычный пользователь уже имеет checkpoint. Подготовка
**внутри каждого публичного запуска** — импорт, CUDA-контекст, чтение файлов,
создание модели/сетки, загрузка, вычисление и MAT — входит целиком.

## Матрица и часы

Одна и та же модель, сетка17³×31=152303 значений. Пакеты128/2048,
последний неполный пакет111/751. По три последовательные повторные пары
на пакет, всего12 свежих Python-процессов. Порядок правил меняется между
повторами: eager/analytic, analytic/eager, eager/analytic.

Часы родителя начинаются непосредственно перед `subprocess.run` и заканчиваются
после завершения дочернего процесса, включая MAT/log I/O и завершение CUDA.
Перед каждым процессом конфигурация последовательно меняет только batch и
исполнение; одинаковый checkpoint сохраняется. Родитель не выполняет обучение
или параллельную измеряемую GPU-нагрузку.

Каждый CLI остаётся в `C:\Projects\pinn-runner`, использует абсолютный pinned
`run.py`, `-B`, общие блокировку/Job Object/защиту снимка. Небольшой загрузчик
выключает TF32; его импорт и запись диагностических runtime-метаданных при
завершении **также входят в часы**. У всех12 процессов проверяются фактические
FP32/TF32, GPU и peak allocated/reserved. Это не профилировщик и не CUDA-event
измерение отдельных ядер.

Свежим является процесс, не машина: кеши ОС/файлов/драйвера не сбрасываются.
Общие APPDATA/LOCALAPPDATA/MPLCONFIGDIR находятся внутри каталога опыта.
Результат не называть запуском на полностью холодной ОС или драйвере.

## Критерий окончания до запуска

Глобальный таймаут600с, у отдельного CLI90с, без автоматического увеличения.
Все12 полей должны быть конечными, иметь форму4913×31; внутри каждой пары
и пакета обязателен точный SHA массива MAT. Между пакетами — контроль
rtol2e-6/atol2e-6, поскольку размер GEMM может менять округление FP32.

Для каждого batch медианное отношение полного времени analytic/eager≤1,10,
худшая пара≤1,25. Худшие отношения peak allocated и peak reserved≤1,10.
Это заранее заданные пороги отсутствия заметной регрессии; прохождение не
объявляется ускорением. Полный отрицательный результат сохраняется при
compare=false, повтор для подбора порога не назначается. Неполный результат
диагностируется штатно без ручной подстановки completion-маркеров.

Полные checkpoint/MAT/log остаются Windows `.gpu-jobs/ID/r`, в Git —12 строк,
контрольные суммы, краткий результат и математические ограничения.
Нового fixed-grid кеша или компиляции нет: их окупаемость не измеряется
и не возникает автоматически из этого опыта. Время обучения и качество
решения остаются за своими независимыми сериями.
