# TASK-28: удалённая исследовательская очередь

## Результат

Реализованы `submit`, `status --remote --job-id`, `cancel`, `collect --remote`.
Управляющий Python не импортирует Torch. Протокол читается из опубликованного
Git-объекта, его байты проверяются по SHA-256; код обучения закреплён отдельным
полным SHA. Новый процесс использует снимок, общий прежний GPU-замок,
внутрипроектные кэши и контролируемое дерево потомков. Повторный ID не создаёт
новую копию; при отличающемся запросе отклоняется. Подробный контракт и команды:
[API](research-workflow-api.md).

Контракт манифеста2 фиксирует архитектуру, режим точности/версии и точный список
граней. Временные профили/веса не передаются агенту. Компактный сбор сначала
проверяется на Windows; конечные пары ещё раз проверяются локально. Состояние
процесса и доказательство качества имеют разные поля.

## Математическая интерпретация

Этот тест доказывает связность API, не точность решателя. Целевые пороги
затухающей моды не выполнены: `candidate_final_target_passed=0`,
`candidate_confirmed=0`. Парные критерии при этом выполнены — два одинаково
неточных метода могут сохранить сопоставимое качество. Малый бюджет и один seed
не используются для оценки ускорения или выбора основных настроек.

Математический оператор, начальные/граничные условия, аналитическое обратное
правило и оптимизаторы не менялись. В результат добавлены конфигурация сети и
параметры среды. Прежнее независимое вычисление `eager/general/autograd` сохранено.
Точное множество граней проверяет наличие ожидаемых операторов на дискретных
контрольных точках; оно не доказывает непрерывной точности PDE или правильности
самого эталонного случая. Для этого остаются математические выводы и отдельные
проверки физического поля/производных. См. [инварианты](agent-research-context.md).
