## Проект и предпочтения

Репозиторий: https://github.com/AridanWarlock/pinn-runner.
Mac: `/Users/user/Documents/ChatGPT/pinn_runner`, ветка `codex/robin-box`.
Это одноразовый файловый решатель в Docker, не сервер. Входы — `config.yaml`
и `functions.py`; `initial_conditions` обязательны в постановке. `data.mat`
для обучения/предсказания не нужен. Эталон в бенчмарке используется только
для независимой оценки, не как учитель. Обратные задачи пока исключены.
Публичный `retrain` начинает новую оптимизацию из весов, не продолжает
автоматически историю Adam/L-BFGS.

Цели: 1D–3D, параметры семейства задач, пространственные поля коэффициентов,
читаемый типизированный код. Основная инфраструктура уже есть. Сейчас приоритет —
точность и стоимость теплопроводности на декартовых прямоугольниках, особенно
точных условий Неймана/Робина. Обновление библиотек отложено. Идею радиуса r
пользователь отложил; не возвращай её без нового решения.

Пользователь пришёл из типизированных языков: явные типы, Ruff, strict mypy,
небольшие понятные объекты вместо огромных методов. Объясняй ключевые изменения
и математические предпосылки по-русски. Формулы — отдельными блоками `$$ ... $$`.
Обычные слова переводить; имена API сохранять. Тематический коммит примерно
на законченный блок работы; отдельная ветка для каждого коммита не нужна.
Допустимо вырезать ненужную совместимость, сохраняя физический смысл.

## Текущие настройки и архитектура

По умолчанию общие ограничения `soft`; внутри `hard_initial_robin` —
`robin_grouped`, `hard_lifting: recursive`, `time_power: 0`.
**Новое значение по умолчанию — `training.backward: auto`**: `parameters` только для
`hard_initial_robin` на одном CPU/CUDA с `32-true`, иначе `all`.
Явный `all` сохраняет контроль. Явный `parameters` разрешён на одном CPU/CUDA
с FP32 и для других постановок как дополнительная опция.
Бенчмарки сохраняют контроль `all` по умолчанию независимо от решателя.

`parameters` здесь — обучаемые веса, не входные параметры вроде κ.
Внутренние координатные производные PDE сохраняются. Только конечный обратный
проход не накапливает `.grad` координат, которыми оптимизатор не управляет.
Один `PINNModule.backward` используется Adam и L-BFGS, явные `inputs` имеют
приоритет. Режим не меняет физическую сигнатуру весов.

Основные точки входа:

- `runner/settings.py`, `runner/backward.py`: схема и разрешение политики.
- `runner/problem.py`: `ProblemAdapter`. **`residuals()` возвращает поля вместе
  с невязками; для функционала выбирай имена уравнений**, иначе добавится штраф за u.
- `runner/factory.py`: сборка модели, данных и Trainer.
- `PINNModule.forward`: физическое поле; `model_step`: функционал;
  `predict_step`: включает координатный граф, когда преобразованию нужны производные.
- `training/refinement.py`: фиксированная цель L-BFGS и непрерывная история
  оптимизатора в пределах стадии; значения точек фиксированы, листья графа свежие.
- Проекции/продолжения и `ConstraintPlan` — отдельные объекты.
  Бенчмарки используют полиморфные `BenchmarkCase`.
- `benchmarks/convergence.py`: план, обучение со срезами, независимая оценка.
  Аналитический ответ нельзя смотреть до окончания всех шагов конкретного опыта.

`hard_lifting: expanded` остаётся дополнительной опцией. Прежняя матрица пяти
состояний дала ускорение около 21%, но медианная последняя ошибка ухудшилась
на 6,93%, общая — на 1,64%. Критерий «медианы не хуже» не выполнен. Два новых
сравнения all/parameters на expanded этого решения не отменяют.

## Результат срезов и с чего продолжить

Всего 30 полных CUDA-обучений: 24 основных, 4 со срезами в общем процессе,
2 диагностических в отдельных процессах. Код CUDA — `e307575`; после него
менялись документы и артефакты. Все серии завершены, новые задания не оставлены.
Первый SSH после паузы не отвечал; после просьбы пользователя и минуты ожидания
доступ восстановился. Финальные тесты: 10 аппаратных CUDA / 21,87 с;
10 профильных / 37,72 с (4 CUDA, 6 CPU, 30 остальных исключены).
`working_tree_dirty=true` может отражать старые неотслеживаемые файлы;
не удалять их, отдельно проверять отсутствие изменений отслеживаемых исходников.

На seed 1234 метрики всех срезов общей пары совпали точно. Два соседних успеха:
первый наблюдаемый успех 335,87 с у all и 268,30 с у parameters, подтверждение
351,66 / 280,86 с. Это одна положительная пара, не общая статистика.
На seed 19 прошёл лишь последний срез: подтверждения нет у обоих режимов.
На шаге 100 контрольная PDE-невязка 0,0150012206 чуть выше порога 0,015;
не округлять её в успех и не ослаблять критерий.

В общем процессе seed 19 показал небольшое расхождение после Adam,
усиленное L-BFGS. Диагностический повтор в отдельных процессах дал **точно
одинаковые веса всех пяти срезов** и воспроизвёл исходные модели `f1bf7bb`.
Время 350,43 → 278,99 с, −20,39%, но время достижения по-прежнему не подтверждено.
Сравнены 22 пары сохранений на CPU Windows; конкретная причина внутри CUDA
не установлена, универсальной детерминированности не обещаем.
Данные: `experiments/2026-10-16-backward-convergence.json` и
`experiments/2026-10-16-backward-isolation.json`.

Для сопоставления одноразового runner использовать **новый процесс на один
вариант и одно состояние**. Пример команды ниже. Измерение предсказания
в срезах относится к контрольному eager-оценщику, не к обучавшему robin_grouped;
для фактического пути использовать основной benchmark_solutions.py.

Ближайшие отдельные шаги в TASK-21:

1. Зафиксировать новый протокол пяти пар времени достижения точности в отдельных
   процессах. Можно заранее добавить срезы 75/125 к прежним 0/25/50/100/150,
   чтобы не терять подтверждение при успехе лишь в конце. Не менять пороги,
   не переименовывать старый отрицательный результат в успешный.
2. Разобраться с полным профилем CUDA-ядер: текущий Torch на Windows даёт лишь
   CPU-события, хотя таблица имеет резервные CUDA-времена. Зависимости и драйверы
   без отдельного решения не обновлять.
3. Затем отдельный адаптер представления: сначала отрицательные контрпримеры
   в 1D, физические производные/операторы, потом 2D/3D и численная матрица.
   Косинус и два полиномиальных признака — гипотезы, не готовая реализация.
   Не менять физический смысл загруженных весов без новой сигнатуры представления.

оба файла перехода и TASK-21; не объявлять карточку Done при неполном профиле.

## Строгие правила Windows

Только `ssh aridanPC`, PowerShell, рабочая директория `C:\Projects\pinn-runner`.
Первым действием — `Set-Location -LiteralPath 'C:\Projects\pinn-runner' -ErrorAction Stop`
и проверка `(Get-Location).Path`; при ошибке остановиться. Все временные файлы,
TEMP/TMP/CUDA/Matplotlib-кеши внутри проекта. Не выходить в другие директории.
Никаких CUDA-тестов на Mac и обновлений `.venv` во время измеряемой очереди.
Не выполнять несколько измеряемых GPU-обучений одновременно. Пока CUDA работает,
заниматься независимой работой на Mac; не подтягивать изменённый код в Windows
посреди серии. Обновления библиотек/драйверов ради профиля не делать.

Новые идеи — кэш невязки фона, другой базис, причинное взвешивание — остаются
гипотезами. Кэш требует точной инвалидизации; отключать граф физического поля
для ускорения нельзя. Подробная математика: [учебный файл](CHAT_MATH_TUTOR.md).
