# Предварительная проверка исследовательского протокола

## Цель и команды

До обращения к Windows проверить, исполним ли опубликованный протокол текущим
инструментом, и показать размер серии. Проверка использует стандартную библиотеку
Python: не импортирует Torch или NumPy, не обращается к сети и не записывает файлы.

```sh
python3 -B -S scripts/research.py plan --manifest docs/experiments/2026-10-17-queue-probe-protocol.json
python3 -B -S scripts/research.py plan --manifest protocol.json --details
```

По умолчанию показываются первые пять начальных состояний генератора для каждого
случая; `--details` раскрывает список. Вывод содержит случаи, размерность, две
сравниваемые конфигурации, критерии, число запусков, суммарные шаги Adam,
внешние вызовы L-BFGS и число сохраняемых состояний. Это JSON для автоматического
чтения, а не полный журнал обучения.

Тот же код вызывается локальным `submit` до SSH, подготовкой очереди на Windows
до создания снимка исходников и исполнителем до импорта Torch. Поэтому отдельного
списка допустимых параметров для предварительного просмотра нет.

## Границы проверки

Поддерживается заранее зарегистрированный контракт 2. Проверяются полная матрица
парных запусков, расписание сохранений с начальным нулём, непересекающиеся каталоги
отчётов, известные критерии качества, архитектура, точность FP32 без TF32,
граничные условия и совместимость вычислительных вариантов. Анализ уже полученных
результатов остаётся отдельным маршрутом и не ограничивается этим каталогом.

`benchmarks/catalog.py` хранит только описания случаев: размерность, сетку,
архитектуру и виды граней. Из него строится реестр численных классов и список
допустимых аргументов CLI. Аналитические решения и формулы PDE остаются в
`benchmarks/cases.py`. Случаи перенесены без изменения их математических методов.

Поле `catalog_scope: current_tool_version` существенно: проверяется каталог
установленного инструмента, а не доказанная совместимость произвольной старой
ревизии. Зафиксированный SHA, опубликованный протокол и неизменяемый снимок
по-прежнему проверяются отдельно. Версии библиотек, реальные функции задачи и
производные проверяются исполнителем. Успешный `plan` не доказывает сходимость
или корректность математического решения.

## Математические предпосылки ограничений

Для каждой грани сравниваются поле, ось, сторона и вид условия. Общая запись
оператора Робина имеет вид:

$$
\alpha u + \beta\,\partial_n u = g.
$$

Здесь n — внешняя нормаль; знак производной зависит от стороны прямоугольника.
У Дирихле коэффициент β равен нулю, у Неймана α равен нулю. Текущая проекция
`hard_initial_robin` требует ненулевого β, поэтому предварительная проверка
отклоняет для неё грани Дирихле. Это ограничение реализации проекции, а не
утверждение о невозможности жёсткого задания Дирихле вообще.

`hard_initial_dirichlet` требует только граней Дирихле. `product_rule` относится
к этому представлению; групповые вычисления Робина и аналитические производные
признаков относятся к `hard_initial_robin`. Мягкие ограничения используют
обычный исполнитель `eager`.

Косинусные и полиномиальные признаки Неймана допускаются на чисто неймановских
гранях с совместимым исполнителем. Ненулевые данные на границе могут переноситься
в общий фон: сами по себе однородные признаки не запрещают неоднородное условие.
Явно выбранный статический фон разрешён лишь случаям, где совместимость с
нулевыми неймановскими данными объявлена в каталоге. Автоматический выбор фона
остаётся ответственностью существующего численного кода.

## Что означает бюджет

Если имеется N запусков, A шагов Adam и последнее сохранение после K внешних
вызовов L-BFGS, выводятся N·A и N·K. При S отметках сохранения сохраняется N·S
состояний. Это не число вычислений PDE: Adam использует разбиение выборки,
а L-BFGS может несколько раз вычислять функцию и производные за один вызов.
Оценка времени без измерений не выдаётся.

Не менее двух сохранений позволяет проверить требование соседних успешных
состояний. Даже тогда качество не гарантировано: попадание в абсолютные пороги
и сохранение качества относительно базового варианта оцениваются после обучения.

## Контроль переноса

Независимый компактный CSV сохранён из опубликованной версии до переноса:
19 имён и классов, размерности, SHA-256 полных конфигураций и 57 значений
аналитических решений. Тест сравнивает новый реестр с этим контролем и отдельно
сверяет реальные граничные дескрипторы с каталогом. CSV нельзя пересоздавать из
новой реализации лишь ради прохождения теста.
