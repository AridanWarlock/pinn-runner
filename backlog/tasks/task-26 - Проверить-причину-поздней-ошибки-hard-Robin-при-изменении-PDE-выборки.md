## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
После точных условий Неймана 3D общий L2 около 0.11%, но ошибка позднего слоя относительно затухающей моды 2.6–3.5%. Нужно отделить влияние покрытия области от числа шагов и стоимости вычислений, без аналитического учителя и смены FP32.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Запустить существующим runner контроль 512 точек и вариант 2048 при 2000 Adam + 150 L-BFGS, seed19/1234, hard_initial_robin/robin_grouped. 2. Пока GPU занят, изучить и измерить структуру продолжения Robin; подготовить доказательство и профильные проверки возможной эквивалентной оптимизации отдельно от опыта точности. 3. Собрать независимые метрики и модальные слои, затем решать, нужен ли следующий опыт с обновлением точек. 4. Сохранить raw evidence, ограничения, обновить отчёты и handoff.

Дополнительно проверить модальный баланс ошибки: для собственных функций теплового оператора вывести a_error_prime + lambda*a_error = projection(residual) + boundary_defect. По сохранённым моделям сопоставить прямую ошибку амплитуды с интегралом невязки; проверить квадратурную сходимость, не использовать аналитический ответ в обучении.

Следующий изолированный опыт заранее: добавляем opt-in collocation.time_power=1, преобразование s=U^(1/(p+1)) только при выборке физических времён. Это явно меняет вес PDE-функционала на q(s)=(p+1)s^p, не является прозрачным ускорением и не меняет формулу физических производных. Контроль p=0; seed19/1234,512точек,Adam2000+LB150,recursive lifting. Выполнить только после основной матрицы и изолированного профиля, не менять defaults.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Запущен асинхронный SSH, Windows HEAD95c3378, CUDA2.1/cu118. План: 512/2048 точек, seed19/1234, Adam2000+LB150; каталоги numerical-reports/robin-sampling-512-001 и robin-sampling-2048-001. Основная сессия не ждёт обучение и исследует продолжение Robin.

e5266e8 добавляет независимый modal_heat_balance: a_error_prime+lambda*a_error=R+B с проекцией физической PDE-невязки и измеренным граничным дефектом. Аналитические тесты1D–3D, знак Robin, несовместимая мода;8passed. Полный CPU426passed215.11s, Ruff/format/strictmypy; Windows очередь ещё выполняется. Разница прямого и восстановленного коэффициента включает ошибку временных трапеций.

Первые4обучения95c3378 завершены:512→2048 точек улучшило late mode3.4866→1.2780% и2.6423→1.4012%, PDE.01801/.01562→.01222/.01219. Время~356–362s практически прежнее, peak244.18→924.48MiB. Все strictgates прошли. Дополнительно opt-in time_power1 тестируется отдельно. Полный CPU438passed229.11s; Windows профиль115passed203.81s(87CUDA/28CPU). Новая проверка коэффициента изg/f/h работает без полного аналитического ответа,10CPUтестов; очередная CUDAверификация впереди.

Дополнительно проверяем точную начальную PDE-невязку на общих независимых пространственных точках, а не только временные bins. Найден дефект benchmark holdout: масштабировалось только время, пространство оставалось[0,1]. Исправлено покрытие всех именованных интервалов/параметров;2теста, включая побитовое сохранение старых единичных кубов. Это не меняет уже выполненные текущие CUDA-case оценки.

В окончательной диагностике сверка MAT использует реальный формат ArtifactWriter: координатыпространства отдельно,векторвремени отдельно,полеNs×Nt. Тест создаёт файлы реальнымwriter и ловит сдвигвремени. Предыдущий синтетический плоский тест исправлен до GPUпроверкиартефактов. Дополнительно замечено,что APIresiduals объединяет поляиневязки; новаяпроверкаслоёв отбирает исключительноуравнения. Код665fc17,fast408passed/37excluded,mypy82.
