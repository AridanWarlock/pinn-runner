# TASK-34: публичный файловый цикл Windows/CUDA

`nonheat026` — отдельный перспективный контроль общего файлового контракта
на переносе и Бюргерсе. Он не повторяет серию точности `nonheat025` и не
доказывает точность шести малых fit. Численные формулы и совместимость
данных уже проверены `nonheat024`; исходный soft/eager сохраняется.

Два сценария `test_nonheat_runner.py`, сеть8², seed19,
7 LHS-точек и пакет7, обучающая сетка4×3. На каждую PDE:

1. Публичный train:3 Adam+2 L-BFGS, сохранение итоговой модели.
2. Загрузка через retrain:1 Adam, learning_rate1e-300, weight_decay0,
   без L-BFGS; точное совпадение всех тензоров исходной/загруженной модели.
3. Публичный predict на новой сетке5×6; конечные значения и верные координаты.
4. Публичный retrain:3 Adam+2 L-BFGS; хотя бы один сетевой вес меняется.

Итого8 CLI-процессов,4 обычных fit и2 пробы загрузки. Проверяются soft/eager
в метаданных и исходные грани: только вход слева у переноса, оба конца
у Бюргерса. Проверка расположения хранилищ тензоров в исходной модели
требует записанного CUDA-устройства; один успешный процесс с CPU здесь
не считается GPU-приёмкой. Состояния для сравнения загружаются на CPU.

Среда RTX4070Ti/Torch2.1.0+cu118/CUDA11.8, FP32/highest, TF32 выключен.
Тот же contract6, неизменяемый снимок, общая GPU-блокировка, разрешённый
каталог Windows и штатные collect/compare. Конкурирующего обучения нет;
запуск только после окончания `nonheat025`. Таймаут180с, без автоматического
продления. Критерий окончания —2 полных исхода с проверкой всех фаз pytest
либо зафиксированная ошибка/таймаут. Отказы и исходные журналы сохраняются.

[Машинный протокол](experiments/2026-10-20-nonheat026-lifecycle-protocol.json)
закрепляет отдельные SHA кода/тестового файла и фиксированный список nodeid.
До публикации прошли fast920/61 e2e исключены, Ruff/format, strict mypy134;
два затронутых файловых CPU-сценария отдельно прошли за14,79с.
Обучающий решатель серии качества не менялся: дополнен только тестовый
контроль устройства и список разрешённых сценариев очереди.
